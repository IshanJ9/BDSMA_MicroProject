# AirWatch — Dashboard & Visualization Layer (Member 3)

## 1. Executive Summary

This module implements **Member 3: Dashboard Development, Data Visualization, Integration, and Presentation** for the BDSMA microproject *AirWatch: Urban Pollution Hotspot Detection Using Big Data Analytics*.

The visualization layer acts as an environmental intelligence interface built using **Streamlit**, **Plotly**, and **Folium**. It directly consumes the compact analytical Parquet outputs generated by Member 2's Apache PySpark engine without re-processing or duplicating the underlying 46.9 million raw hourly observations.

## 3. Global Filtering Mechanics & Granularity

A critical design feature of Big Data spatiotemporal systems is **multi-tier analytical aggregation**:

### A. Geographic Filtering (State & City)
- **Supported Datasets:** `station_summary`, `hotspots`, `episodes`, `spatial_hotspots`, `threshold_sensitivity`.
- **Behavior:** Slices data dynamically based on the sidebar's **Filter by State** and **Filter by City** dropdowns.
- **Affected Visualizations:**
  1. **Executive Overview:** Top hotspots bar chart ranks stations within the selected state/city; Executive KPIs recalculate for the local region; Geographic map zooms into the filtered stations.
  2. **Pollution Hotspots:** Donut classification chart breaks down station categories specifically for the selected state/city; Hotspot ranking bar displays local leaders; Map and records table isolate regional monitors.
  3. **Pollution Episodes:** Episode count, average duration, and worst peak cards recompute for regional stations; Duration histograms, station frequency bars, severity scatter matrices, and chronological timelines display regional runs; Threshold sensitivity evaluates classification stability for the local cohort.
  4. **Station Comparison:** Dynamically populates the station selector with monitors belonging to the chosen state/city for head-to-head analysis.

### B. Nationwide Macro-Baseline (Temporal Profiles)
- **Dataset:** `temporal`
- **Behavior:** Grouped strictly by `(parameter, hour)`, `(parameter, date)`, and `(parameter, month)` across all 538 stations in India.
- **Why it is nationwide:** Aggregating diurnal cycles (00:00–23:00 IST), 365-day anomaly Z-scores, and monthly seasonal curves across the entire CPCB network establishes a robust statistical baseline that reveals national-scale atmospheric boundary layer collapse (morning and night rush-hour spikes) and post-monsoon winter inversions (October–January), independent of local sampling noise.

## 6. Viva & Academic Defense Guide

### Q1: Why doesn't the Diurnal / Temporal chart change when I select a State?
> **Answer:** In our Big Data pipeline architecture, Member 2's PySpark analytics aggregates 46.9 million records across the entire continuous ambient air quality network (538 stations) into a **macro-level temporal baseline**. This reveals fundamental atmospheric phenomena common across urban India—such as morning rush-hour peaks (08:00–10:00 IST) and nocturnal boundary layer trapping (20:00–23:00 IST). Localized spatial analytics are instead handled dynamically by the **Pollution Hotspots**, **Pollution Episodes**, and **Station Comparison** tabs, which slice all station-level tables by State and City.

### Q2: Why does the dashboard read Parquet files instead of querying PySpark live?
> **Answer:** PySpark is designed for heavy distributed batch transformations over 46.9 million raw records. Running PySpark queries interactively inside a web application would introduce latency (10–30 seconds per interaction) and require high-memory cluster resources on the dashboard server. By having Member 2 write pre-aggregated, Snappy-compressed Parquet tables, Member 3's dashboard reads only compact analytical summaries (a few megabytes) into memory via Pandas and PyArrow, achieving sub-second interactive response times.

### Q3: How do you prevent misleading rankings from stations with sparse data?
> **Answer:** We enforce observation-count reliability checks. In Member 2's classification logic, any station with fewer than 24 valid hourly readings is categorized as `insufficient_observations` and disqualified from hotspot status. Additionally, our Station Comparison view prominently displays reading counts and active days alongside mean concentrations so that high averages caused by localized sampling bias are immediately detectable.

### Q4: How does AirWatch align with the UN Sustainable Development Goals?
> **Answer:**
> - **SDG 11: Sustainable Cities and Communities (Target 11.6):** AirWatch isolates high-persistence urban pollution hotspots, providing city administrations with empirical evidence to deploy targeted traffic and emission controls.
> - **SDG 3: Good Health and Well-being (Target 3.9):** By mining multi-hour consecutive pollution episodes, the platform identifies prolonged exposure risks associated with adverse acute respiratory and cardiovascular outcomes.
